# Inplain.ai v0.1.0 Review Runbook

Purpose: verify v0.1.0 internal milestone acceptance criteria (AC-1 through AC-7) and capture review evidence.

## 1. Environment and boot

Prerequisites:
- Docker
- Python 3.13+
- Node.js + npm
- Optional for full manual review: Clerk test keys

Setup:

```bash
make dev-up
make venv
make migrate
```

Run services in separate terminals:

```bash
make dev-api
make dev-web
make dev-worker
```

Optional (render fallback path only): install Playwright browsers once.

## 2. Deterministic checks (command-driven)

Run these before manual browser checks:

```bash
make lint
make test
```

Focused acceptance tests:

```bash
PYTHONPATH=apps/api .venv/bin/pytest -q apps/api/tests/test_api_documents_integration.py
PYTHONPATH=apps/api .venv/bin/pytest -q apps/api/tests/test_pipeline_integration.py
PYTHONPATH=apps/api .venv/bin/pytest -q apps/api/tests/test_acceptance_ac_5_7.py
```

Expected:
- `test_api_documents_integration.py` verifies watch flow internals (watch creates documents and enqueues initial fetch).
- `test_pipeline_integration.py` verifies diff -> summary (with citations) -> notification.
- `test_acceptance_ac_5_7.py` verifies paused-on-404, blocked-by-robots rule, and dead-job behavior after 5 failures.

## 3. Manual browser checklist (AC-1 to AC-4)

Note: AC-1/AC-3/AC-4 manual checks require Clerk auth configured in `apps/web/.env.local`.

1. AC-1 watch flow:
- Open `http://localhost:3000/companies/google` signed out.
- Click `Watch changes`.
- Complete Clerk auth and return to `/companies/google`.
- Verify document cards render and show `First snapshot pending...` until worker fetch completes.

2. AC-2 pipeline result visibility:
- On Google page, click `Check now` on a tracked document.
- Wait for worker cycle completion.
- Verify a new change card appears in `Changes` when meaningful text changed.
- Open the change event and confirm summary bullets include citations.

3. AC-3 citation navigation:
- In `/change-events/[id]`, click a citation pill (`h*`).
- Verify page scrolls to the matching diff hunk and temporary highlight is applied.

4. AC-4 tier enforcement:
- Use a Free-tier user.
- Reach 5 tracked documents.
- Attempt to watch another company/document that would exceed the limit.
- Verify action is blocked and upgrade CTA is shown.

## 4. Failure-mode checklist (AC-5 to AC-7)

Use deterministic tests from section 2 as the acceptance source of truth.

Mapping:
- AC-5 -> `test_ac_5_404_sets_document_paused`
- AC-6 -> `test_ac_6_robots_disallow_sets_blocked_and_rule`
- AC-7 -> `test_ac_7_fetch_fails_5_times_job_is_dead`

UI confirmation (optional):
- AC-5: status copy shows `URL no longer accessible`.
- AC-6: status copy shows `Blocked by robots.txt` and includes blocking rule text.
- AC-7: status copy shows `Last check failed`.

## 5. Evidence to attach to internal review

- Command output for:
  - `make lint`
  - `make test`
  - `make typecheck`
- Screenshot of:
  - watched company with pending snapshot
  - change event summary + diff
  - citation click/highlight behavior
  - upgrade CTA on blocked watch action
- Commit SHA under review (`refresh` branch tip).
