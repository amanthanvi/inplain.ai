# Inplain.ai v0.2.0 Launch Runbook

Purpose: execute and verify launch milestones `L1` through `L15` in a repeatable order.

## 1) Preconditions

- `make lint`
- `make test`
- `make typecheck`
- `make catalog-validate`

## 2) Cloudflare + Clerk hardening (L4 + L5)

Cloudflare:
- Enable orange-cloud proxy for apex + `www`.
- Set SSL mode to `Full (strict)`.
- Keep HSTS enabled at app level.

Clerk Turnstile:
- Enable CAPTCHA in Clerk Dashboard (Turnstile provider).
- Confirm sign-up flow blocks account creation until CAPTCHA passes.

## 3) Railway services (L6 + L7 + L8)

Renderer service (`renderer`):
- Queue scope: `INPLAIN_WORKER_QUEUES=render`
- Disable scheduler + stale-lock cleanup for renderer service.

PostHog service:
- Deploy self-hosted PostHog in Railway project (template services are internal-only).
- Rename template `Web` service to `posthog-web` to avoid ambiguity with the Inplain `web` service.
- Deploy `posthog-proxy` (from this repo) to expose PostHog Web via Railway `$PORT`.
- Set `POSTHOG_UPSTREAM` (or `POSTHOG_WEB_UPSTREAM`) on `posthog-proxy` to the **private** PostHog Web URL (including port `:8000`).
  - Recommended in this project: `POSTHOG_UPSTREAM=http://posthog-web:8000`.
- Set `POSTHOG_CAPTURE_UPSTREAM` on `posthog-proxy` to the private PostHog Capture URL (typically `http://capture:3000`).
  - Keep `Capture` internal-only (no Railway-provided domain).
- Set `POSTHOG_API_KEY` + `POSTHOG_HOST` (the `posthog-proxy` public URL) on `api` and `worker`.
- Set `NEXT_PUBLIC_POSTHOG_KEY` + `NEXT_PUBLIC_POSTHOG_HOST` on `web` (optional; reserved for client-side tracking).
- If a direct `railway variables --set ...` triggers an unexpected source deployment failure, re-run with `--skip-deploys` and continue incident response with the last healthy deployment.

Sentry:
- Set `SENTRY_DSN` on `api` and `worker`.
- Set `NEXT_PUBLIC_SENTRY_DSN` on `web`.

### Railway private-network recovery (production)

If Railway shows `Error updating private network - automatic repair triggered` with a large pending apply set:

1. Run `make railway-prod-check` for a deterministic baseline.
2. Confirm only `api`, `web`, and `posthog-proxy` are public in production.
3. Verify private network endpoints are healthy (`syncStatus=ACTIVE`).
4. Check `environmentStagedChanges` for a stale patch with `lastAppliedError`.
5. If stale patch exists, reset staged changes to `{}` via `environmentStageChanges(..., input:{}, merge:false)`.
6. Re-check `environmentStagedChanges` and then run production smoke verification:
   - `railway run --service api --environment production -- make smoke-test`
7. If the only remaining issue is a failed latest `posthog-proxy` deploy warning, recover with `deploymentRollback` to the last known-good deployment ID. Avoid `railway down` for this case.

## 4) Deploy verification (L9 + L10)

Blue-green rollout:
1. Deploy to green.
2. Run smoke checks against green.
3. Switch traffic to green.
4. Monitor for 15-30 minutes.
5. Roll back on errors.

Smoke checks:

If PostHog is configured, include `POSTHOG_HOST` + `POSTHOG_API_KEY` to validate event ingestion.

```bash
WEB_BASE_URL=https://<green-web-domain> \
API_BASE_URL=https://<green-api-domain> \
INTERNAL_SERVICE_TOKEN=<token> \
POSTHOG_HOST=https://<posthog-domain> \
POSTHOG_API_KEY=<posthog-project-api-key> \
make smoke-test
```

Tip: to run the smoke test locally **without copying secrets**, you can pull production variables via Railway CLI:

```bash
railway run --service api --environment production -- make smoke-test
```
